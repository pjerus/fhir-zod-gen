### The one that mattered most

#23 was filed with the wrong root cause. It claimed `extension` being `0..*`
is domain knowledge not derivable from the data, and proposed hardcoding the
two field names. It *is* derivable: `DomainResource.extension` states
`array: true` outright, and `resolveDocumentOverBaseChain` was terminating the
walk two levels below it, on the stated assumption that a "true base
resource/type" is "already self-sufficient". It isn't — `translate()` emits one
differential layer per document, so a `specialization` states only its own.

The reported symptom was one wrong flag. The actual defect: **every** generated
schema was silently missing `id`, `meta`, `implicitRules`, `language`, `text`,
`contained`, `extension`, `modifierExtension`, and every datatype was missing
`id`/`extension`. Hardcoding would have fixed the symptom and left six of eight
fields missing everywhere.

Same root cause turned up in three more places before the session was done:
`resolveTypeElements` (datatypes), primitives with attached children (their
children are an `Element`), and BackboneElements (`modifierExtension` from
BackboneElement, `id`/`extension` from Element). Rule now in CLAUDE.md: *if
you're tempted to hardcode a FHIR base field because "it can't be derived",
check one rung further up the chain first.*

### What the example ratchet caught

It found or caught five things reasoning did not. This is the sharpest tool in
the repo; keep feeding it.

- #23, #24, #27 themselves (the sweep that filed them).
- **Slicing matcher bug**: the converter is inconsistent about wrapping a
  pattern for a repeating field — US Core writes `{code:{coding:[{system,code}]}}`,
  genomics-reporting writes `{coding:{system,code}}` for the same
  always-an-array `CodeableConcept.coding`. 57 of 81 conformant
  genomics-reporting examples were rejected. Would have shipped.
- **A regression I introduced mid-PR**: the BackboneElement fix *assigned*
  the inherited map instead of merging under it, discarding everything the
  profile chain had resolved and collapsing every backbone child to `unknown`.
  Test pins it now.

### Vacuous-pass trap, closed

`validate-examples.ts` generated *without* `primitiveRegex`, so it would have
kept reporting 441/441 while proving nothing about the regex feature — the
exact closed-loop failure this project was rebuilt after. It now generates with
the same options the CLI does. **If you add another `EmitOptions` field, wire it
into that harness in the same commit.**
