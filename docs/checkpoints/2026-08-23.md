### #42 — the registry answer was the opposite of the obvious one

The issue's suggested first step was to check whether `packages2.fhir.org`
serves the missing `us.nlm.vsac@0.18.0`. It does — and it makes no difference.
`fhir-package-installer@1.13.1`'s `getTarballUrl` returns the identical
npm-style `{registry}/{id}/-/{id}-{version}.tgz` in **both** branches of its
`isPrivateRegistry` check; the two branches are character-for-character the
same, a distinction that doesn't exist. packages2's real layout is
`/packages/{id}/{version}` → 302 → `/web/{id}-{version}.tgz`, which that URL
shape never reaches. **No `registryUrl` value fixes this**, so graceful
degradation is the entire fix, not half of it. Recorded in CLAUDE.md so nobody
re-derives it.

`hl7.fhir.us.davinci-pas#2.2.1`: **0 → 64 files**, compiling as a set. Its
`PASSubscription` document is still reported-and-skipped (its
`backport-subscription` base isn't in the declared closure) — the existing

### #40 — the narrowing goes back where it belongs

A named-type reference now carries a field-local `.superRefine()` re-applying
whatever requiredness *that occurrence* states beyond the shared file's
consensus. Chosen over `.and()` (bad inferred types) and over per-variant
datatype files (file-count + naming work). 55 re-applied requirements across
15 files in us.core, 35/9 in r4.core, 2/1 in sdc, 0 in mcode.

Spot-checked against the **raw StructureDefinitions**, not just our own
pipeline: US Core Practitioner's re-applied set is `identifier.system`,
`identifier.value`, `name.family` — exactly what its differential states.

Deliberately shallow (top-level fields of the occurrence only). The nested
case has no evidence behind it and a real open question about which consensus
to compare against.

### #41 — measured first, then written

Census of all 266 distinct constraints in us.core + r4.core, weighted by the
158 markers us.core's output actually emits: `A.exists() or B.exists() [or …]`
is 63 of them. The apparent runner-up, the `field.matches('…')` family, is 35
distinct rules and **zero** emitted markers. So exactly one shape is
translated.

Three refusals are the load-bearing part, and all three are in CLAUDE.md now:
all operands resolve or the whole rule is abandoned; `severity: "warning"` is
never enforced; and a `value.exists()` operand is a **choice group** resolving
to its flattened `value[x]` variants — read as a plain key it would have
rejected every conformant instance in existence.

Enforced: 72 r4.core, 64 us.core, 55 mcode, 26 genomics-reporting, 4 sdc.
